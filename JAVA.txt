    1. 정의: 소프트웨어 개발에서 사용되는 디자인 패턴으로 세가지 주요 역할 분리하여 모듈화(조각)
    2. 목적: 협업간의 코드와 파일들을 mvc패턴 따라 구성하여 효율성 높임
    3. 장점: 유지보수, 모듈화, 단일책임기능( SRP: 단일 책임 원칙 - 객체지향 5대원칙(SOLID) ) 등
    4. 단점: 분리함에 따라 관리 복잡도 높다.
        예시] 식당 - 역할별로 담당 분리 ( 단일 책임 원칙)
    5. 사용처: 웹/앱 백엔드 사용.
    6. 레이어/계층
        - View : 입출력 담당 , HTML/CSS/JS/REACT/FLUTTER 등
        - Controller : model - view 사이에 제어 / 로직 / 유효성검사 / 전달 담당, JAVA/PYTHON/NODE.JS
        - Model : 데이터 관리 담당 , JAVA/PYTHON/NODE.JS 
    7. 이동객체
        DTO : 서로 다른 레이어/계층 간의 데이터 객체, setter and getter 지원
        VO : 서로 다른 레이어/계층 간의 데이터 객체, getter 지원
    8. 흐름
        게시물쓰기 : view --> DTO/VO --> controller --> DTO/VO --> DAO/REPOSTORY <--> 데이터베이스(SQL)
        게시물조회 : view <-- DTO/VO <-- controller <-- DTO/VO <-- DAO/REPOSTORY <--> 데이터베이스(SQL)
    9. 패키지 구성
